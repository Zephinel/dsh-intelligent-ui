# Changelog

Notable changes to `@zephinel/dsh-intelligent-ui`. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions are the
published npm versions. `Unreleased` collects changes on `main` that have not
been published yet.

## [Unreleased]

### Added

- **Editable structural blocks (M4-6).** The block editor no longer treats `Caption`, `Divider`, `Spacer`, `Toc` and a root `Title` as page chrome: every direct child of the root `Col` and of the seven nested containers is an editable block. New block kinds (`divider`, `spacer`, `toc`, `heading`, `caption`) carry localized panel labels and glyphs; titles come from Title/Caption text, the first Toc items or the first text. Structural operations, `orderByParent`, additions, cross-container moves and target-order normalization now accept these nodes like any other block (with a per-type page-order fallback for untitled pieces), while the real safety rules stay: `@Each`/opaque/shared/depth limits, and duplicating subtrees containing Section/Toc anchors. Verification: **510 Node tests**, 9/9 browser suites, artifact-edit **321 checks**, nested-edit-renderer 75; client CSS 213.2 kB; pack 44 files 4.25 MB / 11.00 MB.
- **Divider/Spacer quick adjust (M4-6).** `Divider(color?, width?, thickness?)` and `Spacer(width?, height?)` join the component props, grammar and prompt: a divider can paint a theme token or CSS colour, take a centred px/% width and a 0.5–12px thickness; a spacer accepts px/%/auto width and height and stops flexing when sized. Selecting one of these blocks opens a **quick-adjust** panel instead of the model-instruction textarea (colour/width/thickness, or width/height) with a **live canvas preview**; applying sends one deterministic `props` operation to the existing structure route, where the Host validates the bag, rewrites the named statement definition through `replaceNodeContent`, and records a revision with the usual idempotency/branch/CAS rules. The result appears as a **Property revision** local card, and applying is refused while instructions, ordering or a global note are pending. Verification: 510 Node tests, 9/9 browser suites, artifact-edit **321 checks** (quick panel, canvas preview, request body, property revision card, dirty refusal, dynamic fallback, custom controls); pack 44 files 4.25 MB / 11.00 MB.
- **Input focus is now an orbit glow.** Every text input, textarea, select and field-like trigger in the extension (card chrome, artifact editor, popovers, settings, template fields and model-composed form inputs) gets the same traveling-light focus cue. A document-level `InputOrbit` layer measures the focused field and draws the ring; the field's own focus outline, colored focus border and halo are suppressed while the orbit is active. Checkboxes, radios and ranges keep their native treatment.
- **Borderless edit panel.** The docked/bottom-sheet editor is now a borderless floating surface: the outer 1px border was removed in both the desktop rail and the mobile sheet; its background, radius and soft shadow still separate it from the page. E2E asserts the panel border width is zero.
- **Orbit glow breathes.** The traveling border light sat only 3px outside the block; it now sits 10px out with a 22px corner radius, so the light reads as a separate halo rather than hugging the content edge.
- **Focused editing hides every orbit glow.** While a block editor is open, the other root blocks now drop their orbit glow entirely (the scrim already dims them); before, the glows stayed painted above the scrim and competed with the block being edited. Save/Cancel restores them, with pending blocks keeping the slower/dimmer glow.
- **The real left-edge line: row hover hairline removed.** ego-browser inspection showed the marked line was not the grip focus outline but the row's `box-shadow: inset 1px 0 0`, which paints a rounded vertical line only at the row's left edge (top/bottom/right invisible). Row hover/focus now uses the neutral background only; no left-only border remains.
- **One separator before the global instruction.** The panel had both an explicit `.dsh-iui-edit-divider` and a `border-top` on the global-instruction section, painting two hairlines a few pixels apart (visible whether or not the nested arrangement section was rendered). The section border-top was removed; the explicit divider remains the single separator.
- **Redundant toolbar Exit editing removed.** The card header already offers Exit editing and the edit panel header has its own exit, so the third copy in the toolbar was removed; both remaining exits keep the shared quiet outlined style (the panel exit also carries the legacy data hook for flows that used the toolbar control). This leaves the toolbar to the level/protection controls and the request drawer. E2E asserts the toolbar copy is gone (artifact-edit: 321 checks).
- **One Exit editing style everywhere.** The card header used a pressed blue border/text while the toolbar and panel headers used different neutral buttons. All three now share the same quiet outlined exit treatment (same height, padding, surface, hover and focus ring); the card header no longer paints the pressed accent, so entering/leaving edit mode no longer looks like two different products.
- **Quieter arrangement rows, real Locate glyph, clearer mode copy.** The panel rows were polished: page-order numbers are now plain tabular figures (bordered chips removed), the five row actions stay hidden until hover or keyboard `:focus-visible` (a mouse click no longer keeps them visible after the pointer leaves), row hover is a neutral surface with a hairline instead of a blue tint, the edited tag became a dot + text, and the drag grip loses its hover box/glow in favour of a hairline focus ring. The Locate button now uses a `map-pin-line` glyph, clearly distinct from the four-arrow move icon: the earlier `focus-3-line` name was absent from the plugin's inline icon subset (so it rendered empty) and, once added, still read too close to the move control; the action group was widened for five controls. The toolbar controls are now compound button groups (current level/state | action + chevron | info), so they read as controls rather than input fields: the level group shows `Top level` / `Nested` plus the action `Show nested blocks` / `Back to top level`, and the Strict protection group shows a status dot, the label and `on/off`. The info buttons live inside their group and open plugin-drawn tooltips (portaled, themed, hover/focus/click, Escape, aria-describedby) instead of native `title` tooltips. The per-mode banner was replaced with one static editing hint so the action label and the status line can no longer disagree. A new unit test scans every literal `<RemixIcon name="…">` against the inline path table so a missing glyph cannot silently render as an empty slot again.
- **Nested blocks join the row/canvas mapping.** Hover sync, hover frames, page-order addresses and the Locate button now work for nested rows too (addresses such as `1.2.1` appear while that nested block is hovered); the browser suite covers nested hover, linked rows, nested Locate and its flash.
- **Legacy pages without an authoritative base fall back cleanly.** Cards rendered before the authoritative program registry (or whose program was evicted) cannot persist deterministic property writes; the quick panel now switches to the instruction editor with an explanation instead of leaving a dead Apply button. Such pages can still be edited through the model, or re-rendered to get an authoritative base.
- **Panel ↔ canvas mapping, focus mode and quiet pending markers.** Arrangement, nested and request rows now hover-sync with the canvas (a neutral frame on the block, a matching row tint), root blocks show their page-order index while nested blocks show it on hover, and every row has a **Locate** button in addition to clicking the row body. Opening a block editor dims the rest of the canvas with a scrim and keeps the edited block's frame; closing it restores everything. Saving an instruction no longer leaves the block in the big selected state: the selection becomes a quiet pending marker (coloured dot + request number) and the root orbit glow returns slower and dimmer; the request still ships unchanged. The animation is documented as an orbit glow / traveling border beam rather than a marquee, and the code/CSS names follow that terminology with a legacy class alias.
- **Custom quick-adjust controls and sliders.** The quick-adjust panel no longer uses native `<select>` widgets (their popups are OS-painted and clash with the dark editor) or a native range input: colour and unit pickers are a themed listbox with keyboard navigation, and Divider width/thickness plus Spacer width/height gain a plugin-drawn slider. Dragging the slider updates the canvas preview immediately (zero model calls); Apply still records the property revision. Focus, Escape handling and the portaled menus stay inside the popover's interaction flow.
- **Quick-adjust popover stays pinned and sliders drag precisely.** Previews that change a block's width/height used to re-anchor the instruction popover through its ResizeObserver, so a Divider narrowing to 60% moved the panel — and the slider track under the pointer — mid-drag, making the value jump. The popover now captures its placement at open and only re-anchors on real user scroll/resize or when the target block changes; layout-induced scroll anchoring and the panel's own internal scrolling are ignored, so switching the width unit (px ↔ %) no longer moves it either. Slider dragging is relative to the pointer-down value (clicking the track no longer teleports the thumb), so nudges stay small; the browser suite asserts the popover keeps its left/top while a width preview changes the anchor geometry.
- **Long article pages can be edited (200-node CST budget).** The CST budget was 60 nodes, which silently disabled nested editing and quick adjust on realistic long pages (the Solid 2.0 guide has 105 nodes: the nested Spacer disappeared and the "Nested blocks" button never rendered). The budget is now 200, so long pages keep root editing, nested blocks and deterministic property overrides; the large-page regression is covered by a 66-node fixture in the browser suite.
- **Block popover focus ring is no longer clipped at the bottom.** Focusing the block-instruction textarea drew a 2px focus ring whose bottom edge was cut off: the textarea is the last field in the popover scroll box, and that box had no bottom padding inside its `overflow-y: auto` clipping area (left/right had already been fixed with 3px textarea margins). The scroll box now reserves 4px of bottom padding, so the full ring stays visible on all four sides. Artifact-edit E2E now has **260** checks (left and bottom ring room, reserved scroll padding). Verification: 496 Node tests, artifact-edit **260** checks, browser 9/9; CSS 205.0 kB.
- **Icon-free edit affordance animation and panel exit.** Editable blocks no longer brighten and dim their body, and no icon is added. Each **top-level editable block** now carries a small **comet of light that orbits its invisible edge** every 2.6 s, with a fading tail and a soft glow; blocks run it at staggered phases and each one uses its own **washed-out pastel tone** (blue, purple, green, amber, pink, cyan) from the edit palette, so the canvas reads as lively without a hard accent or a permanent border. Hovering a block brightens its orbit, a selected or instruction-open block keeps its rounded card lift, and `prefers-reduced-motion` holds the glow still instead of orbiting. The ring is a conic gradient masked to the rounded 1.5px border area of the root block wrapper only (nested children never draw one), so corners stay continuous and there is no layout box, padding or extra layer. - Host edit pipeline, deterministic arrangement and revision registry: a prepended `session/event` observer parses the `<artifact-edit-request>` envelope from real user messages (15-minute TTL, at most 64 pending sessions), verifies block targets and the complete `targetOrder` permutation against the base program, allows empty edits, rejects no-op requests and applies the edit after ordinary validation, rejecting a style/styleId mismatch, a temporary style and a stale base revision. When the order changed, the Host ignores the client hint and reorders the model's updated root `Col` children deterministically by mapping blocks back through statement name → title + component type → unique title (chrome slots preserved; a failed mapping returns a retryable error without consuming the request). `render_ui` gains the optional `program` output field alongside `artifactId`/`revisionId`/`baseRevisionId`/`revision`/`editedBlockIds` and the `presentationMeta` projection; edits render `Interactive UI updated for the user (revision N of the artifact, K blocks edited).` and order-only updates render `... block order adjusted).` Revisions are stored atomically in `$DSH_HOME/dsh-intelligent-ui-artifacts.json` (immutable records, at most 400) and exposed by the authenticated exact route `GET /api/intelligent-ui/artifact-revisions?artifactId=&revisionId=`. The envelope carries the editing and reordering rules, and `skills/intelligent-ui/SKILL.md` names how to apply it.
- **Block-fragment editing (M2 Phase 1):** a new `edit_ui_blocks` tool edits only the selected top-level blocks. The shared `artifact-block-bundle.ts` extracts a bundle (selected block expressions resolved to their right-hand sides, the transitive frozen statements and `$state` they reference, and the page outline) and `spliceBlockBundle` deterministically puts the model's mini program back: exactly one `root = Col([...])` child per selected block in request order replaces only those root-child slots, chrome/root arguments/base statements stay byte-identical, new helper statements are appended, and collisions, duplicate/unknown ids, count mismatches and undefined references reject with a retryable error before the composed page is re-parsed and re-counted. The Host composes the page, applies the deterministic `targetOrder` normalization and records the revision; the tool result carries `{artifactId, revisionId, baseRevisionId, revision, editedBlockIds, program, title?, style, styleId?}` in its `presentationMeta`, and the client's `programs.ts::blockEditProgram` renders the revision card from that meta (`edit_ui_blocks` process rows reuse the compact `RenderUiRow`). The content-edit envelope and injected prompt instruct one `edit_ui_blocks` call with only the edited target blocks; order-only/global-only requests keep the full-program `render_ui` path, and `render_ui` now rejects content-edit requests with "call edit_ui_blocks" while keeping the request armed. Phase 1 still sends the full page as read-only reference context — the input-token savings move to Phase 2.
- **Edit robustness and live target-order preview (M1):** the composer chip reference is now deterministic (`artifact-edit:<sessionId>:<baseRevisionId>`) so it resolves after a reload; an orphaned reference yields a `stale` outcome and the localized `edit.errorStale` message instead of the old misleading revision message. Failed `render_ui`/`edit_ui_blocks` tool rows show one short readable reason beside the state (recorded result text, then structured error reason, whitespace-collapsed and clipped to 160 characters with the full text in the title; program arguments are never read). While editing, a 15-second interval plus window focus/visibility calls the silent `probeArtifactRevisionStatus`, which only raises the existing conflict banner (never auto-clears a conflict), so a concurrent update is visible before Send. The edit canvas reorders the real block wrappers to `targetOrder` with a **Previewing the target order** toolbar marker; the stored revision and exports stay unchanged until Send. Below 720px block editing is unavailable: the card and an active edit view show a minimum-width notice with a dismiss/exit action (owner decision B0-1).
- **Partial-failure reconciliation (M3-1c):** every edit revision now carries its `requestId` in the result meta (`ArtifactRevisionMeta.requestId`, populated by the Host on both the `edit_ui_blocks` and `render_ui` paths and read back into the client program), so a sent draft can be matched to the revision it produced. Submitted drafts are retained as `status: 'submitted'` with `requestId`/`submittedAt` (at most 12 unresolved submitted drafts per chat, oldest dropped). Once the Turn closes, the client reconciles that Turn's submitted drafts (using a `turn.start - 5s` … `turn.end` send-time window so historical Turns cannot claim newer submissions): drafts whose `requestId` appears in the Turn's cards are deleted, while unfulfilled drafts return as editable, detached drafts marked `submitFailed`, with a fresh `requestId` and a cleared `submittedAt`. The card draft badge gains a **Not completed; draft kept** state (`data-state="failed"`) and the panel switcher an `is-failed` tag; activating or re-attaching a failed draft clears the marker, and attach adds it back to the next Send — there is no automatic retry or resend.
