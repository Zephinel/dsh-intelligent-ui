# 样式与编辑整合（已完成，2026-11-08 工作树）

## 结论

样式不是独立功能，是 Artifact 编辑里的一种操作类型；但它不能和内容编辑合并成同一种操作。

- 区块/整页编辑：改 program 的内容或结构；
- 样式切换：绑定持久皮肤（内置或模板），零模型，program 逐字节不变；
- 样式说明（B1）：模型改写外观，产出 temporaryStyle；
- 保存模板：把样式快照登记进样式库，不产生修订，不属于编辑。

统一点是「一个 Artifact、一条修订线、一个样式入口」，不是「一种操作」。区块编辑的细粒度在内容轴，样式是正交轴；两者产生同一种修订，但执行路径和保证不同。

## 样式切换能保证什么

不承诺任何 A→B 都成功，也不承诺切换后视觉等同模板的生成效果。承诺：

> 可用即成功，不可用先禁用；竞态失败不静默换样式，同一操作重试可收敛。

- **可预判并置灰**：Article 目标不满足 Host 的 Toc/Section/anchor 谓词；当前已是该样式；当前修订非最新（显式 branch 除外）；有区块草稿；已填写样式说明。
- **不可预判，Host 兜底**：选择后模板被删除/隐藏、其他标签新增修订、program 登记被淘汰、存储失败。
- Article 谓词移到 shared（`src/shared/article-layout.ts`），客户端与 Host 使用同一实现，避免「先允许、后报错」。
- 当前/最新检查：非 branch 的旧修订直接禁用并只显示一条状态；显式 branch 允许切换，绝不自动 branch。
- 请求复用 `styleSwitchOperationId`：响应丢失后重试同一个 operationId，Host 幂等 ledger 返回已记录结果，不把重试变成 `base_not_latest` 或重复修订。

## 保存

保存模板是独立动作，不是编辑步骤：

- 只有带完整 theme 的临时样式结果（B1/按需）显示「保存为模板」；当前位于结果/修订卡，不进入编辑器。
- 样式切换结果不保存：内置本身不可保存，已保存模板已经是模板。
- theme-less 临时样式没有可复用主题，不显示保存。
- 保存不产生修订；应用样式才产生修订。

## UI

样式区保留一个入口，目标按「内置样式 / 已保存样式」分组，中间分割线；所有目标同一 radio group，单选互斥。

- Article 行不可用时禁用，并在列表下用一行普通语言说明原因。
- 每次只显示一条状态：检查中／非最新／有区块草稿／已填样式说明／选择目标／不适用／当前已选／可应用；应用后分支或临时样式状态使用对应提示。
- 移除常驻的 3–4 段说明；零模型、临时样式替换等信息合入状态行。

## 边界（已文档化）

- 模板是 live reference：修改模板主题会影响旧切换修订；删除模板回退内置主题。当前不冻结每个修订的 theme。
- branch 下的样式切换沿用显式分支，不自动 branch。
- 不合并 block/style 请求或修订；不把样式说明改走结构路由。
- 不隐藏不可用目标（保留稳定列表并用禁用原因教会规则）。
- 不承诺 directives 被执行，也不承诺模板冻结。
- 不重写 store/管线。
