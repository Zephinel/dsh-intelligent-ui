# 已知限制

[English](limitations.en.md) | [返回 README](../README.md)

本文只列**当前版本**仍存在或尚未验证的边界；已实现的行为见[使用指南](usage.md)和[架构与行为](architecture.md)。

## 运行环境与兼容性

- DSH 插件接口按 **0.2.2** 开发，实际验证版本是 **0.2.2-rc.1**（当前最新）；更晚的 DSH 版本未验证。
- 构建/测试/发布工作流使用 **Node.js 24**；仓库没有 `engines` 或 `.nvmrc` 版本锁。
- 已验证平台是 macOS（Web + DSH Desktop）与 Windows（DSH Desktop）；Linux 未验证。
- 浏览器半边要求部署组合 `@deepseek-ai/dsh-client-locale`（DSH Web 0.2.2 默认包含）；最小自定义 profile 缺少它时开关和卡片不挂载。
- 插件详情页依赖 `dsh-settings` / `dsh-client-ui-settings`；交互页面导出依赖 `webServer`。最小 profile 缺少这些服务时对应 UI 不出现。
- client bundle 更新后必须**重启 `dsh-web`**，刷新页面不够。

## 问答与渲染

- 卡片在该轮**结束时**出现；生成过程中进程区只显示一行「交互式回答」。
- 模型可能生成不合法的 OpenUI Lang；Host 会返回精确校验错误，通常同一轮内自修（实测 1–2 次），但不能保证成功。
- 生成提示词约 10K tokens，仅在开关命中该会话时发送；关闭时工具 schema 和提示词都不出现。Article 页面更长，输出 token 和渲染时间相应增加。
- 地图底图依赖 OpenFreeMap 瓦片，路线依赖 OSRM demo，照片依赖 Wikipedia/Wikimedia；离线时地图降级为地点列表，照片降级为占位块。
- KaTeX 依赖 DSH 壳层已加载的全局样式；该样式被移除时 `Math` 会退化为纯文本。
- `/iui` 的 Host 回复、命令面板描述和 README 截图保持英文；浏览器 UI 文案才跟随 DSH 语言。

## 导出

- 图片导出不包含沙盒 iframe（`HtmlView` 小游戏）里的内容；地图依赖 WebGL 缓冲，禁用 WebGL 时按地图自身的降级显示。
- 同一轮多张卡片会合并成一张图片，导出的是**当前交互状态**（勾选、筛选等），不是初始状态。导出会等待图片/图片搜索就绪，最多约 12.5 秒；未就绪时按页面占位状态导出。
- 交互页面导出会把渲染器、主题和全部卡片内联进单个 HTML，文件较大（约 3.4–4.9 MB），地图/照片等仍依赖网络。`@ToAssistant` 依赖剪贴板；剪贴板不可用时只能手动复制提示文本。
- 临时样式、模板和按需状态不会随导出 HTML 提供跨设备编辑；导出的是当前渲染结果。

## 模板与样式

- 模板文件交换格式为 v1，单次最多 **32 KiB（UTF-8）**；只导入交换格式，不接受原始模板导出文件或持久化库备份。全局最多 40 个模板，每会话 20 个。
- 导入只创建全局模板；本会话范围导入尚未开放。没有分享码、在线链接、批量备份或批量导入。
- 外部模板名称和展示规范会进入提示词，属于不可信文本；阅读确认和不自动应用是缓解措施，不能消除提示词注入。真实部署的 Origin/CSRF 与工具越权审计仍建议补做。
- 自定义明暗主题只应用到 renderer host；portaled Popover 和沙盒 iframe 保留默认主题。导出交互页面会冻结导出时的明暗方案。

## 按需生成、草稿与多标签页

- 按需操作只在内存中：等待发送（armed）10 分钟过期，重启后无法恢复；已完成结果不受影响。每会话最多一个活动操作；已绑定 running/clarifying 时不能重新武装，最多两轮澄清。
- 按需提示只显示在发起标签页，但 Host 绑定该会话的下一条人工消息，不验证实际发送标签；请在发起标签页发送。
- 未提交编辑草稿按标签页写入 `sessionStorage`：刷新可恢复，但**跨标签不共享**；`branch`、`latestRevision`、`submitFailed` 和撤销记录不持久化，超大 program 不写入。
- 跨标签编辑租约基于 BroadcastChannel：只提示、不合并修改、不阻止继续编辑；频道不可用时无提示，Host 的修订校验仍是最终权威。

## 区块编辑与结构操作

- 可编辑范围是根 `Col` 的所有直接子区块和七个 allowlisted 容器内部的直接区块；`@Each`、opaque 表达式、共享命名表达式、page chrome 和超深/超节点预算的页面不可编辑。CST 节点预算为 **200**，长文章页面可能因此被拒绝。
- 顶层顺序必须恰好包含基础版本的全部顶层区块（最多 100 个）；模型返回的内容修改片段由 Host 合并，未选区块保持逐字节不变。
- 一次请求最多 12 条内容修改；修改说明最多 2,000 字符，整体说明最多 4,000 字符；没有变化的请求会被拒绝。
- 严格保护只检测**识别到的顶层未选区块**；选中根区块内部、未被选中的嵌套子节点改动不会被检测。
- 自然语言样式调整会把已保存/内置样式的页面转为结果自有（临时样式）修订：模型未给 theme 时继承会话主题而非原模板主题，原模板主题延续留待后续；历史来源显示为「区块编辑」+ 临时样式徽标；旧 Host 或不可编辑卡片不提供编辑内样式区、临时结果仍显示底部「调整样式」回退（是否已登记 base 不影响样式区展示，缺 base 时发送/应用才报错）。每个临时样式修订会在结果注册表多存一份快照（既有 LRU 上限）。
- 确定性样式切换（零模型）只换样式身份、外壳与主题：模板的 directives 不会重排既有内容（需要模型重绘）；Article 目标要求页面带可用目录和章节，不满足时客户端禁用、Host 拒绝（`article_unavailable`）；已保存模板是 live reference，改主题会影响引用它的旧切换修订，删模板回退内置主题；branch 切换沿用显式 branch，不自动 branch；结果记录为本地修订卡，不进入助理消息、transcript replay、图片/交互页面导出或其他设备；H4 已修——样式切换后 `render_ui` 的 order-only/global-only 编辑使用 artifact 记录样式，不再按会话样式被拒（内容编辑 `edit_ui_blocks` 不受影响）；`sessionStyleScope` 只是 session 模板的可见性作用域，不是授权边界；保存模板只适用于带 theme 的临时样式结果，创建新模板且不覆盖内置/已有模板；内置、已保存模板和普通结果没有保存入口；不提供更新原模板或复制已保存模板；保存不产生修订。
- 结构操作支持复制、删除、同父/跨容器移动和每容器一个新增区块；不支持把嵌套区块移动到 root、跨容器只追加到目标末尾、没有多步 undo/GC，删除不清理 helper 声明。Carousel 离屏子项 anchor 可能需要绘制时裁剪，尚未实现。
- 结构操作会直接关闭当前草稿（`markSubmitted`）；「结构改变导致内容草稿过期」的确认 UI 尚未提供。
- 旧页面不需要手动迁移：第一次打开编辑、修订历史或恢复时，客户端会自动把当前渲染内容登记为 Host 的权威基础（写一次、不覆盖），随后结构操作、历史与恢复即可用。仍存在的边界：旧 Host（无登记路由）与新 Client 混合部署时登记不可用，相关操作回退到指令编辑或重新渲染；未被任何权威操作触达的旧卡保持未登记（无后台迁移）；被 LRU 淘汰的非当前修订 program 无法从客户端重建；登记的初始修订在历史里显示为登记时间。权威 registry 最多 200 条 / 50MB program。
- 本地结构/属性修订卡存在浏览器 `localStorage`，只在触发的 Turn 渲染，不进入 assistant 消息，不参与图片/交互页面导出，换设备会丢失。
- 修订历史删除是**不可恢复**的 Host 真删：初始渲染不可删；仍被其他修订当作 `baseRevisionId` 的修订会被拒绝（409 `revision_referenced`），需先删更新的修订；当前卡正在渲染的修订禁止删除；删除最新（若不属于当前卡）后，其他仍在渲染该修订的卡片会持续处于 stale 状态，直到下一次权威操作或重新渲染；其下一次编辑/发送会按 stale 失败；删除 base 后仍引用它的草稿在发送时会被 Host 按 stale 拒绝，结构路由返回 `base_missing`，恢复路由返回 `source_missing`；删除不清理由同一 `operationId` 产生的结构操作幂等 ledger 记录。
- 多个 Artifact 的编辑请求相互独立，没有跨 Artifact 事务：一条失败不会回滚其他成功修订。Turn 结束后按 requestId 对账；未完成草稿会恢复为「未完成，草稿已保留」供重新附加，不会自动重发。Host pending 仍有 15 分钟 TTL；Turn 归属使用发送时间窗口启发式，极端时钟/长延迟场景未验证。
- 真实模型的「部分成功」路径尚未做真机验证；已在真机覆盖单卡、双卡、嵌套编辑和结构操作的主要成功路径。

## 运行时状态与可访问性

- 运行时状态快照只在浏览器会话内存，刷新即丢失；容量为 24 个 Artifact、每 Artifact 5 个修订快照、单快照 ≤64KiB。首渲染不继承历史状态，只有带 `baseRevisionId` 的新修订才继承；第三方组件内部状态和编辑画布内交互值不保留。
- 编辑画布支持屏幕阅读器和纯键盘操作，但没有真实 screen-reader/axe 审计；live region 是单个 polite 槽位，快速连续重排会合并播报，指针拖拽只在 drop 时播报。
- 输入框轨道光晕的 forced-colors/touch 行为由 Chromium CDP 模拟验证；真实 Windows 高对比度、iPad/Safari 和深色主题下的对比度尚未实测。
- 视觉基线是手动对照（5 张 PNG），没有自动像素 diff；只在 390×844、900×1000 和桌面宽度做了布局验证，更多设备/浏览器组合未覆盖。
- `npm run check` 不包含需要 Chrome 的浏览器套件；没有 PR CI，发布由 tag 触发的 GitHub Actions 完成。`tsc` 不检查 `src/client`（DSH 平台类型不在本地依赖中）。
