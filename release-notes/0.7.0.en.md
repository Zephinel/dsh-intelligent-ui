## Highlights

- Explanations now embed charts, flows and small interactions directly in the answer text; standalone itineraries, dashboards and forms still arrive as an editable page card at the end of the turn.
- Auto mode now supports four deliveries: text, inline UI, a turn-end page, or an inline explanation plus one page card; an answer renders at most one card and never duplicates content.
- A new app icon, shared by the Plugins page and the update prompt.
- Chinese and English UI copy now use one term per concept, correct singular forms and no internal jargon.
- Custom popovers stay inside the visible area when you pinch-zoom.

## Details

0.7.0 collects the changes on main since 0.6.2: an explanation stays Markdown, and when a chart, table, flow or small interaction helps, the model writes a complete program into an `openui` code block that the client renders inside the message; a standalone page (itinerary, dashboard, tool, form, game) still calls `render_ui` for an editable turn-end card. The two forms may share an answer with distinct roles, but an answer renders at most one card and never duplicates content; the Card / Article setting only chooses the layout of standalone pages, while document mode and on-demand turns stay cards. The app icon is new, and the update prompt carries the same mark. Custom popovers now position against the visual viewport (`window.visualViewport`), so pinch-zoom no longer pushes them off screen. Chinese and English UI copy follow plain-language rules with one term per concept, correct singular forms and no internal jargon; the README is a visual-first documentation index. Known limits: docs/limitations.md.
